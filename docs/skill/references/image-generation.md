# 生图这一半（Seedream）

生图与视频是两条独立链路：**同步接口、无任务 ID、无轮询**。别为了「架构统一」把生图塞进视频的任务表。

## 最小可用链路

```
normalizeImageOptions(input)   // 校验 + 归一化，CLI 与网页共用
      ↓
buildImagePayload(opts)        // 组请求体（含尺寸折算）
      ↓
generateImages({ apiKey, payload })   // 一次 POST，同步等结果
      ↓
saveOne(item, dir, base, i)    // 逐张下载落盘，返回结构化结果
```

`runImage()` 包一层做落盘与汇总；`runImageBatch()` 做连发多张；`runImageCompare()` 做多模型并行对比。三者返回同构的结果对象，CLI 打印、网页转 JSON 都吃它。

## 尺寸怎么算

档位（`1K`/`1.5K`/`2K`/`3K`/`4K`）给的是**长边**：

1. 按比例把长边分给长边、短边
2. 两边都取 8 的倍数（`round(n/8)*8`，最小 64）
3. 夹到官方区间：单边 ≤ 4096，总像素 ∈ [1280×720, 4096×4096]
4. 越界就按比例整体缩放，最多迭代 8 次
5. 还越界就报错（说明档位与比例组合不可行）

```
1K + 1:1   → 1024×1024
2K + 9:16  → 1152×2048
1K + 9:16  → 720×1280   ← 不是 576×1024，被最小像素数抬上来了
2K + 21:9  → 2048×880
```

允许直接写 `2048x1152` 绕过折算。

## 连发出图（为什么不是一次要 N 张）

平台一次请求只保证返回 1 张（`max_images` 实测无效，见 `pitfalls.md`）。所以：

```
count = N  →  循环 N 次单张请求，每次独立落盘，文件名带 -r1 / -r2 序号
```

- 第 1 次就失败 → 立刻抛出，不继续（说明是配置问题，继续只是烧钱）
- 第 2 次之后失败 → 记录到 `errors`，继续跑完，最后汇总「要 3 张成了 2 张」
- 全部失败才算整体失败

**耗时是线性的**：单张 15 秒，4 张就是 1 分钟。UI 上要给进度（第 i/N 张），否则用户以为卡死了。

## 多模型对比

同一提示词并行调 2–4 个模型，每个出 1 张，横向比效果。用 `Promise.all`，每个 slot 独立 try/catch——**未开通的模型单独标失败，不能拖垮其他模型**。

```
cost = Σ 成功张数 × 各自单价
```

这是「选模型」这个决策最短的路径：一次花 4 毛钱，比看四篇评测有用。

## 网页上的六件事

| 功能 | 实现要点 |
|---|---|
| 提示词模板 | 独立 localStorage 键 `ark.templates.image.v1`，与视频模板互不干扰；同名再存是更新 |
| 三种传图 | 按钮选文件 / `Ctrl+V` 从剪贴板贴 / 拖拽进参考图格。粘贴走 `paste` 事件的 `clipboardData.items`，取 `getAsFile()` |
| 参数区 | 模型、尺寸档（按模型能力动态显示）、比例、张数、水印、格式（仅当模型支持多个格式才显示） |
| 多模型对比 | 勾 2–4 个模型，走 `/api/image-compare`，结果分组横排 |
| 历史记录 | 键 `ark.image.history.v1`，存提示词+模型+尺寸+张数+费用，点一条回填重跑，最多留 60 条 |
| 产物三连 | 每张图下三个按钮：以此为参考 / 用作视频首帧 / 用作视频参考图。后两个自动切到视频 tab 并填槽位 |

产物三连是这个控制台最实用的一处联动：生图 → 挑一张 → 直接当首帧出视频，不用下载再上传。

## 深链

`#image` 直接打开生图页。用途：把链接贴给别人，或在脚本里 `start "" "http://127.0.0.1:5199/#image"`。

实现：`hashchange` + 首次加载各判断一次，切换 tab 时同步写 hash。

## 模型不在表里怎么办（必做的一个出口）

模型表是本地维护的，厂商每上线一个模型就得补一条。所以 UI 必须留「＋ 自定义 Model ID」：

- 下拉最后一项固定是 `＋ 自定义 Model ID…`，选中后展开输入框，填完整 ID（如 `doubao-seedream-5-0-flash-260915`）
- 提交时把输入值当作 model 传给服务端；`resolveImageModel` 对未知 ID 原样透传，交给服务端校验
- 自定义模型的能力未知：档位放开常见值、价格显示「以官网为准」、不让它参与多模型对比
- 输入的 ID 存 `localStorage`，下次打开还在

没有这个出口，用户开通了新模型却看不到，只能来问「为什么没有 XX」——这个问题会无限重复。

## 可选字段按能力带，不按值带

`sequential_image_generation` 在 4.0 / 4.5 / lite 上正常（`disabled` / `auto`），在 5.0 pro / flash 上
**连 `disabled` 都是 400**。所以组包规则是：

```
model.group === false  →  整个字段不出现
count > 1              →  "auto" + max_images
其余                    →  "disabled"
```

在模型记录里加 `group` 字段，比在组包函数里写 if-else 判断模型名稳得多。

## 验证清单

```
node bin/ark.js image "测试" --dry-run                  # 请求体正确，不花钱
node bin/ark.js image "一只绿色玩偶，纯白背景" --size 1K   # 约 ¥0.2
node bin/ark.js image "四种配色" -n 2 --size 1K          # 必须真出 2 张
node bin/ark.js image "奶蛙" --compare seedream-4.0,seedream-4.5 --size 1K   # 约 ¥0.45
```

四条都过，才能说「生图能用」。只跑第一条等于没验证——dry-run 不发请求，证明不了 Key、开通状态、尺寸合法性。
