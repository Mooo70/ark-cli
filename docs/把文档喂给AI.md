# 怎么让 AI 把文档变成脚手架

这套脚手架不是手写的。流程只有三步：**抓文档 → 定规则 → 让 AI 按规则写**。

## 第一步：把官方文档变成 AI 能吃的 markdown

不要丢一个网页链接给 AI（它会瞎猜参数）。打开官方文档，把这几页的内容整理成 `docs/<模型>.md`：

| 要抓的页 | 抓什么 |
|---|---|
| 创建视频生成任务 | 请求地址、鉴权、**全部请求体字段与默认值**、返回结构 |
| 查询视频生成任务 | 路径、`status` 取值、`content.video_url`、`usage` |
| 模型能力/使用必读 | 分辨率档位、时长范围、比例、任务类型硬约束、素材上限 |
| 价格页 | 各分辨率单价 |

写法就照 `docs/seedance-2-5.md`：分九节（基本信息/请求体/参数表/任务类型/素材规格/返回结构/价格/像素表/同系列）。**字段名一个字都不能改**，这是后面 AI 写代码时唯一的对错标准。

一页大概 1–2 千字就够，比原文短 90%，但参数表必须完整。

## 第二步：写 AGENTS.md（决定成败的一步）

同一份文档，给 AI 一句话和给 AI 一套规则，产出差很远。`AGENTS.md` 要写四件事：

1. **目录职责**——哪个文件干什么，改哪类需求动哪个文件
2. **硬规则**——不许硬编码模型 ID、参数名必须对齐文档、校验集中在一个函数、不发请求的路径要能跑通
3. **扩展流程**——加新模型走哪五步
4. **验证清单**——改完必须跑哪几条命令

有了它，AI 第二次改代码不会推翻你的架构。没有它，三轮之后项目就散了。

## 第三步：让 AI 生成/维护代码

在 ZCode / Cursor / Claude Code 里，工作目录选到 `ark-cli/`，然后：

**首次生成（从零）**

```
读 AGENTS.md 和 docs/seedance-2-5.md，按文档在 docs 之外实现一个零依赖 Node CLI。
要求：
- bin/ark.js 入口，src/cli.js 参数解析，src/ark.js 组请求+轮询+下载，src/models.js 存模型 ID 与价格
- 命令：config set api-key / video / task / models / cost
- 必须有 --dry-run（只打印请求体）和 --selftest（离线断言，不发请求）
- 参数名严格照文档，不要用 SDK，不要引入依赖
- 先写代码，再跑 --selftest，全绿再交付
```

**日常改需求（这才是真正的价值）**

```
我想用脚手架调 Seedance 2.5 生成一个视频：一只小猫在河边玩，突然河里跳出一条鱼，
它叼着鱼走远。用最省钱的方式，清晰度不用高，但要有环境音和背景音乐，画面要真实。
帮我生成调用命令，并解释每个参数在做什么。
```

AI 会翻 `docs/` 里的参数表，产出类似：

```bash
ark video "夏日傍晚的乡间河边，一只三花小猫蹲在水边玩耍…（三段动作）…镜头跟随，浅景深，自然光，毛发与水面反光，细节真实。环境音：潺潺流水、鸟鸣虫鸣、鱼跃水花，轻快温暖的背景音乐。" \
  -R 480p -d 8
```

它甚至会提醒你 480p 每秒 0.672 元、8 秒约 5.4 元——因为它读的是你 `models.js` 里的价格表，不是网上的旧文章。

**加一个新模型**

```
把 docs/seedance-2-0.md 加进项目：先在 models.js 里加一条，再补 selftest 断言，跑通为止。
```

## 提示词本身也值得固化成文档

视频作者那条 8 秒片的提示词有固定结构，可以直接写成模板放进 `docs/提示词模板.md`：

```
【场景锚定】时代 + 地点 + 光线（示例：夏日傍晚，乡间小河边，逆光）
【动作三段】起（静止状态）→ 转折（意外发生）→ 收（结果动作）
【镜头与质感】镜头运动 + 景深 + 自然光 + 材质细节（毛发/水面/反光）
【声音清单】环境音 A、B + 音效 + BGM 情绪
```

模型靠「动作细节」和「声音清单」才不会丢物体、不会让主体停在原地。
